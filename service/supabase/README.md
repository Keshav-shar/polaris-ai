# supabase/

**Purpose:** The Supabase CLI project for Polaris: `config.toml` (local stack: Postgres + Auth only, realtime and
storage off) and the forward-only SQL migrations that define the permanent store (`docs/data-model.md`). Replaces
the README-only `service/db/` (C137): the CLI reads migrations from `supabase/migrations/` and nowhere else.

**May depend on:** Nothing. Executed by the Supabase CLI only (`npm run db:start | db:reset | db:push`).

**Must not depend on:** Application code. TypeScript never imports from here.

**Contents:**
- `config.toml` — generated by `supabase init`, then: `project_id = "polaris"`, `site_url = http://localhost:3000`,
  redirect allow-list `http://localhost:3000/auth/callback`, realtime / storage / seed off
- `migrations/` — `0001`-`0012` (see its README)

**Design notes:**
- Local JWTs use the CLI's default HS256 secret, which the service's JWKS verifier deliberately refuses (no
  shared-secret tokens, C105). Integration tests therefore cover storage and RLS, not sign-in; for a local
  sign-in run, generate an asymmetric key with `supabase gen signing-key` and set `[auth] signing_keys_path`.
- `.temp/` and `.branches/` are CLI state and gitignored by `supabase/.gitignore`.
